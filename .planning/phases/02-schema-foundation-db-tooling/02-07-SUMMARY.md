## Decisions Made

- **Custom migrate runner instead of drizzle's migrate():** Drizzle's `migrate()` reads
  `_journal.json` and runs ALL entries without a filter API. The requirement to skip seed
  entries while keeping them in the journal (for Plan 09 drift check) needed a custom
  implementation. The custom runner mirrors drizzle's `readMigrationFiles()` logic with an
  added tag filter.
- **SEED_TAG_PATTERN = /seed/i regex on tag field:** Simple, readable, forward-compatible.
  Any future seed-like migration can be named `NNNN_seed_*.sql` and will be skipped
  automatically. Pattern is case-insensitive to prevent accidental inclusion if capitalization
  varies.
- **db:seed points to src/db/seed.ts (not migrations/):** Scripts in `src/db/` follow the
  existing project convention (`migrate.ts`, `reset.ts`). Keeping seed.ts alongside them
  makes the runner scripts consistently discoverable. The `migrations/` folder holds only
  SQL content, not TypeScript runners.
- **sql.unsafe() in seed.ts:** The seed file uses a `DO $$ ... END $$;` PL/pgSQL block,
  which is a multi-statement construct. The postgres.js tagged template API only handles
  single parameterized queries; `sql.unsafe()` is required for raw multi-statement SQL execution.
