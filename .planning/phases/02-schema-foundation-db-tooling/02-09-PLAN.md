    Step 1 — Create `scripts/check-migration-drift.mjs`:
    ESM module (no TypeScript needed — runs directly with `node`).
    Algorithm:
    1. Read `packages/core/migrations/meta/_journal.json` — parse entries array
    2. Read `packages/core/migrations/migration-hashes.json` — stored hashes `{ "<tag>": "<sha256>" }`
    3. For each entry in journal:
       a. Construct filePath: `packages/core/migrations/${entry.tag}.sql`
       b. If file does not exist: `console.error('DRIFT: missing migration: ' + filePath); driftDetected = true; continue`
       c. Compute SHA-256: `createHash('sha256').update(readFileSync(filePath)).digest('hex')`
       d. Compare against `storedHashes[entry.tag]`:
          - If no stored hash: `console.error('DRIFT: no stored hash for ' + entry.tag); driftDetected = true`
          - If hash differs: `console.error('DRIFT: ' + entry.tag + ' modified since commit'); driftDetected = true`
    4. If `driftDetected`: `process.exit(1)` with error message listing all drifted files
    5. Else: `console.log('Migration integrity check passed — no drift detected.'); process.exit(0)`
    Imports: `readFileSync`, `createHash` from node builtins. No external deps.

## STRIDE Threat Register

| Threat ID | Category | Component | Disposition | Mitigation Plan |
|-----------|----------|-----------|-------------|-----------------|
| T-2-01 | Tampering | schema drift between environments | mitigate | Committed migration-hashes.json + CI check-migration-drift.mjs script exits 1 on any edit; primary defense per D-35 |
| T-2-02 | Tampering | migration-hashes.json itself edited | accept | If hashes file is also edited, git diff --name-only will show both files changed — reviewer/PR check covers this; two-person rule for migration changes is a process control |
