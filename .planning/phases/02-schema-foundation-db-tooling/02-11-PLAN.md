    ADR-001 (0001-postgres-as-ledger-engine.md):
    Use the full skeleton from RESEARCH.md Pattern 8 as the base. Expand "Considered Options" section with TigerBeetle evaluation from SUMMARY.md. Key drivers: DEFERRABLE CONSTRAINT TRIGGER, pg-boss exact-once, SERIALIZABLE isolation, REVOKE permissions. TigerBeetle cons: no standard SQL, no pg-boss compatibility, no CONSTRAINT TRIGGER DEFERRABLE equivalent, not ACID relational. Con for Postgres: not optimized purely for financial throughput (acceptable at 100 RPS v0.1 target).

    ADR-002 (0002-fastify-http-framework.md):
    Context: Phase 3 needs HTTP framework for REST API. Drivers: TypeScript-first, high throughput, schema validation, ecosystem (swagger). Options: Fastify 5, Hono, Express. Outcome: Fastify — async-first, lowest overhead, coerceTypes: false (prevents silent type coercion on amount_cents), built-in JSON Schema. Consequences: no Express middleware compatibility; good: OpenAPI generation via @fastify/swagger. More info: Phase 3 plan.

    ADR-003 (0003-pg-boss-workflow.md):
    Context: Exact-once webhook guarantee requires enqueue and INSERT into raw_events in same Postgres transaction. Drivers: exact-once guarantee (WHI-04), same TX boundary, no distributed consensus. Options: trigger.dev, BullMQ, pg-boss. Outcome: pg-boss — sole option that participates in the same PG transaction. Consequences: adds PG-side queue overhead (autovacuum tuning needed); good: no separate queue process. Rejected: trigger.dev/BullMQ cannot participate in PG SERIALIZABLE TX.

    ADR-004 (0004-incremental-balance-worker.md):
    Context: account_balance needs to stay fresh. Real-time triggers vs. periodic worker. Drivers: lag < 1s p99 (BAL-06), cursor pattern for restartability, lock for concurrency (BAL-04). Options: AFTER INSERT trigger on postings (synchronous), pg-boss incremental worker. Outcome: pg-boss incremental worker with FOR UPDATE lock and last_posting_id cursor. Consequences: balance update is async (< 1s) not synchronous; trigger approach would block write path.

    ADR-005 (0005-accounting-split-async-settlement.md):
    Context: PIX/boleto payments have async settlement — money reserved at t=0, settled at t+N. Accounting split modeling. Drivers: double-entry purity, v0.1 MVP scope. Options: synchronous posting at capture, async with pending/settlement accounts. Outcome: v0.1 posts at settlement event (webhook). pending_balance reserved (D-45) for v0.5. Consequences: v0.1 balance reflects settled funds only; pending_balance NULL until v0.5.
