    Section A — Trigger function:
    Use RESEARCH.md Pattern 3 verbatim:
    `CREATE OR REPLACE FUNCTION check_double_entry_balance() RETURNS TRIGGER LANGUAGE plpgsql AS $$`
    DECLARE `v_signed_sum bigint;`
    BEGIN:
    `SELECT COALESCE(SUM(CASE direction WHEN 'debit' THEN amount_cents WHEN 'credit' THEN -amount_cents ELSE 0 END), 0) INTO v_signed_sum FROM postings WHERE transaction_id = NEW.transaction_id;`
    `IF v_signed_sum <> 0 THEN RAISE EXCEPTION 'double_entry_violation: transaction % has unbalanced postings (signed sum = %)', NEW.transaction_id, v_signed_sum USING ERRCODE = 'P0001'; END IF;`
    `RETURN NULL;`
    END $$;

    Section B — Constraint trigger:
    `CREATE CONSTRAINT TRIGGER assert_double_entry`
    `AFTER INSERT ON postings`
    `DEFERRABLE INITIALLY DEFERRED`
    `FOR EACH ROW`
    `EXECUTE FUNCTION check_double_entry_balance();`

    CRITICAL: Do NOT add `SET CONSTRAINTS ALL IMMEDIATE` anywhere. Do NOT add `UPDATE` to the trigger events — AFTER INSERT only, since postings is append-only. Per RESEARCH.md Pitfall 1.

    Commit as: `feat(02-05): add 0004_double_entry_trigger migration; constraint trigger GREEN`.
