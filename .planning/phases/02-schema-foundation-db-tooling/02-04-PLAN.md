    Section A — Composite input type:
    `CREATE TYPE posting_input AS (account_id uuid, amount_cents bigint, direction text);`
    This type is the argument shape for the function. Using composite type (not JSONB array) per RESEARCH.md Pattern 2 for PG-level type safety.

    Section B — post_transaction function:
    Use the SECURITY DEFINER function skeleton from RESEARCH.md Pattern 2 verbatim. Key implementation decisions per CONTEXT.md Claude's Discretion:
    - Argument shape: `(p_idempotency_key text, p_description text, p_source text, p_metadata jsonb, p_postings posting_input[])`
    - Returns `uuid` (the transaction id)
    - `SECURITY DEFINER` + `SET search_path = public` (mandatory per RESEARCH.md anti-patterns)
    - Idempotency: SELECT INTO v_tx_id WHERE idempotency_key = p_idempotency_key; IF FOUND THEN RETURN v_tx_id (no error — idempotent return per API-05)
    - Validate array not empty: IF array_length(p_postings,1) IS NULL THEN RAISE EXCEPTION 'post_transaction: postings array must not be empty' USING ERRCODE='P0001'
    - Loop over p_postings: accumulate signed sum (debit=+, credit=-); validate direction IN ('debit','credit'); validate amount_cents > 0
    - Validate signed sum = 0: IF v_signed_sum <> 0 THEN RAISE EXCEPTION 'post_transaction: postings do not balance (signed sum = %)' USING ERRCODE='P0001'
    - INSERT into transactions (id=gen_random_uuid(), idempotency_key, ts=now(), description, source, metadata)
    - FOREACH p_postings: INSERT INTO postings (id=gen_random_uuid(), transaction_id=v_tx_id, account_id, amount_cents, direction)
    - RETURN v_tx_id
    - LANGUAGE plpgsql

    Section C — Ownership and EXECUTE grant:
    `ALTER FUNCTION post_transaction(text, text, text, jsonb, posting_input[]) OWNER TO aprumo_migration;`
    `GRANT EXECUTE ON FUNCTION post_transaction(text, text, text, jsonb, posting_input[]) TO aprumo_app;`
    Do NOT grant INSERT ON postings to aprumo_app here or anywhere — this is the sole write path.
