<objective>
Add a `created_at TIMESTAMPTZ NOT NULL DEFAULT now()` column to the `postings` table so that API-09 cursor pagination has a monotonically-ordered sort key.

Purpose: postings.id is UUIDv4 (random, not monotonic). Per RESEARCH.md Open Question #1 and Pitfall 5, cursor pagination by UUID gives undefined ordering. This migration adds a reliable ordering column. This plan is Wave 1 (parallel with Plan 01) because it modifies only the schema and migration files — no Fastify packages are needed here.

Output: migration 0010_postings_created_at.sql + updated schema.ts + journal entry + hash entry. The [BLOCKING] `pnpm db:migrate` apply step is included so the live DB reflects the new column before any pagination integration test runs.

IMPORTANT: This project uses Drizzle generate+migrate with committed SQL files, NOT `drizzle-kit push`. The flow is: edit schema.ts → `pnpm db:generate` → committed SQL file → `pnpm db:migrate`. Do NOT re-edit migrations 0000-0009 — the drift gate freezes those hashes.
</objective>
