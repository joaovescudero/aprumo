TDD implementation of the two pure-utility layers that all route handlers depend on: the serialization-retry wrapper and the PG-code-to-HTTP error handler.

Purpose: These are the highest-risk pieces of Phase 3. The CLAUDE.md success criterion #4 explicitly states: "withRetryOnSerializationFailure wrapper retries the entire db.transaction() call (not just the failing query) on SQLSTATE 40001". Getting this wrong causes data corruption (retrying only a single SQL statement after 40001 leaves the transaction in an aborted state — subsequent SQL raises 25P02 in_failed_sql_transaction). TDD here ensures the contract is proven before routes use it.

<interfaces>
<!-- withRetryOnSerializationFailure contract -->
Signature:
  export async function withRetryOnSerializationFailure<T>(
    fn: () => Promise<T>,  // factory — called fresh on each retry attempt
  ): Promise<T>

Constants (internal, not exported):
  SERIALIZATION_FAILURE = '40001'
  MAX_RETRIES = 3
  Backoff: attempt 0 = 50ms, attempt 1 = 100ms, attempt 2 = 200ms (50 * 2^attempt)

Retry logic (per RESEARCH.md Pattern 4 + PG docs):
  - Calls fn() up to 4 times (attempts 0, 1, 2, 3)
  - On attempt 0..2: if error.code === '40001', save error, wait backoff, retry
  - On attempt 3: if error.code === '40001', re-throw (exhausted)
  - Any non-40001 error: re-throw immediately (no retry)
  - Success: return value from fn()

PG error code extraction pattern (from PATTERNS.md + applyMigrationsToSchema.ts lines 376-379):
  const pgCode = err instanceof Error && 'code' in err
    ? (err as { code: string }).code
    : undefined;

<!-- LedgerError + SerializationExhaustedError contract -->
class LedgerError extends Error {
  constructor(message: string, readonly code: string, readonly statusCode: number)
  name = 'LedgerError'
}

class SerializationExhaustedError extends LedgerError {
  constructor()  // message: 'SERIALIZABLE transaction failed after 3 retries', code: '40001', statusCode: 503
}

<!-- pgErrorHandler contract -->
Signature:
  export function pgErrorHandler(
    error: FastifyError & { code?: string; validation?: unknown[] },
    _req: FastifyRequest,
    reply: FastifyReply,
  ): void

Mapping table:
  error.validation != null             → 422 { error: 'Validation failed', details: error.validation }
  error.code === 'P0001'               → 422 { error: 'Ledger constraint violation', message: error.message }
  error.code === '40001'               → 503 { error: 'Service temporarily unavailable', retryable: true }
  error.code === '23505'               → 409 { error: 'Conflict' }
  default                              → 500 { error: 'Internal server error' }

SECURITY: 500 body MUST NOT include error.message or stack trace (PG internal details leak).

<!-- Analog: retry loop from applyMigrationsToSchema.ts lines 232-257 (readWithRetry) -->
Key difference from readWithRetry: receives factory () => Promise<T>, not a value.
Error discriminant: code === '40001' not code === 'ENOENT'.
MAX_RETRIES = 3 (not 10). Returns T (not string).
