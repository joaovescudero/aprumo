## What Was Built

This plan creates the test infrastructure that enforces all 10 INF requirements. Per CLAUDE.md "Toda mudança de código de produção começa por um teste falhando" — the Vitest configuration IS production infrastructure, and all tests for config-presence and CI-gate scripts are written RED first.

### Files Created

**Root configuration:**
- `vitest.config.ts` — Root Vitest config with `projects:` array (D-20 AMENDED: not deprecated `vitest.workspace.ts`), inline project for `tests/` directory to allow Wave 0 tests to run before `packages/` exist, plus glob coverage thresholds at 90% for `packages/core/src/**` and 80% for `packages/*/src/**` (specific-before-wildcard order per Research Pitfall 1)
- `package.json` — Root package.json with all devDependencies (vitest, biome, changesets, lefthook, typescript) and scripts including `changeset:check`

**Test scaffold (tests/scaffold/):**
- `infra.test.ts` — 15 it() blocks asserting file existence and content: pnpm-workspace.yaml, package.json fields, tsconfig.base.json (strict + noUncheckedIndexedAccess + NodeNext), biome.json (noExplicitAny=error), .nvmrc, .npmrc, 4 package stubs
- `coverage-gate-fires.test.ts` — Creates `packages/core/src/__fixtures__/uncovered.ts`, spawns `pnpm vitest run --coverage --project=@aprumo/core`, asserts non-zero exit (coverage threshold fires)

**CI gate tests (tests/ci/):**
- `secret-scan.test.ts` — Checks gitleaks binary, .gitleaks.toml, and detects EC PRIVATE KEY + SECRET= patterns (gracefully skips when gitleaks not installed)
- `gitignore.test.ts` — Parses .gitignore and asserts 7 required patterns (.env*, *.key, secrets/, dist/, coverage/, node_modules/)
- `changeset-gate.test.ts` — Asserts .changeset/config.json exists with access, baseBranch, updateInternalDependencies fields

## Deviations from Plan

### Auto-fixed Issues

**1. [Rule 3 - Blocking] Added inline project object for tests/ in vitest.config.ts**
- **Found during:** Task 1 execution
- **Issue:** Vitest 4.x with `projects:` glob `packages/*/vitest.config.ts` fails with "No projects were found" startup error when no packages exist. This prevents Wave 0 tests from running at all (error, not assertion failure).
- **Fix:** Added inline project object `{ test: { name: "root-tests", include: ["tests/**/*.test.ts"], environment: "node" } }` as first entry in `projects:` array. This allows Wave 0 tests to run before any `packages/*/vitest.config.ts` files exist.
- **Files modified:** `vitest.config.ts`
- **Commit:** 59d956f

**2. [Rule 3 - Blocking] Created root package.json in Wave 0**
- **Found during:** Task 1 execution
- **Issue:** Without a package.json, `pnpm install` cannot install vitest, which means the test files cannot be executed to verify RED state.
- **Fix:** Created `package.json` with correct devDependencies and all required scripts. The package.json also serves as Wave 0 infrastructure — its `packageManager` and `engines.node` fields are tested by `infra.test.ts` (these 2 tests pass GREEN since the file is intentionally correct).
- **Files modified:** `package.json` (created)
- **Commit:** 59d956f

**3. [Rule 1 - Bug] Fixed Vitest 4 API breaking change in coverage-gate test**
- **Found during:** Task 1 verification
- **Issue:** `it(name, fn, { timeout })` signature was removed in Vitest 4 (deprecated in Vitest 3). Test file failed with "Signature was deprecated in Vitest 3 and removed in Vitest 4" error.
- **Fix:** Changed to `it(name, { timeout }, fn)` which is the correct Vitest 4 API.
- **Files modified:** `tests/scaffold/coverage-gate-fires.test.ts`
- **Commit:** 59d956f
