CI jobs in ci.yml (D-12, D-13, Pattern 7):
  concurrency: { group: "ci-${{ github.ref }}", cancel-in-progress: true }
  on: pull_request + push.branches[main]

22 + 24) already validates behavior on both versions. Keep coverage-gate on Node 22 only.

<threat_model>
## Trust Boundaries

| Boundary | Description |
|----------|-------------|
| GitHub Actions runner → npm registry | OIDC trusted publishing; no long-lived NPM_TOKEN |
| GitHub Actions runner → git history | gitleaks-action scans full history; fetch-depth:0 required |
| PR author → CI → main | Status checks required; changeset-check blocks missing changesets |

## STRIDE Threat Register

| Threat ID | Category | Component | Disposition | Mitigation Plan |
|-----------|----------|-----------|-------------|-----------------|
| T-1-01 | Information Disclosure | Secret committed and bypassing pre-commit via --no-verify | mitigate | gitleaks-history job scans full git history on every PR/push with --config .gitleaks.toml (custom starkbank-private-key rule applies); cannot be bypassed without GitHub Actions config change (which requires review per D-14 branch protection). |
| T-1-03 | Tampering | CI bypass — direct push to main | mitigate | Branch protection (D-14): PR required, 1 review, status checks. Configured as checkpoint in Plan 06. The CI file itself is in git — changing it requires a PR. |
| T-1-04 | Elevation of Privilege | OIDC misconfiguration leaking npm publish | mitigate | release.yml has environment: release (concurrency lock). npm-side Trusted Publisher config (D-23b) deferred to Phase 9 — no publish risk until then. |
| T-1-SC | Tampering | GitHub Actions supply chain (uses: actions/checkout@v4 etc.) | mitigate | All external actions pinned to @v4 (stable, reviewed releases). gitleaks/gitleaks-action@v2 pinned to major version. changesets/action@v1 pinned. |
</threat_model>
