<objective>
Restore the Phase 1 test suite to fully green by fixing the 3 failing INF-02 assertions in
`tests/scaffold/infra.test.ts`.

Root cause: commit 3a9fc93 (WR-05) added a `// ignoreDeprecations: "6.0"...` line comment to
`tsconfig.base.json`, making it valid JSONC but not strict JSON. The existing `readJson()` helper
uses `JSON.parse()` which throws `SyntaxError` on the `//` comment (position 423, line 17). tsc
tolerates JSONC silently, so typecheck/build pass and mask the failure.

Fix strategy: add a `readJsonc()` helper that strips `//` line comments and `/* */` block comments
before calling `JSON.parse()`. Switch all three INF-02 tsconfig.base.json reads to `readJsonc`.
Leave `readJson` unchanged — it is still correct for genuine-JSON files (package.json, biome.json)
and must not be widened.

No new dependencies. Inline comment-strip regex: zero-dep, matches the project preference.
No `any`, no `@ts-ignore` — per CLAUDE.md conventions.

Purpose: Close UAT gap (tests 1 and 5 blocked). This is a test-infrastructure fix, not a
production code change.

Output: Updated `tests/scaffold/infra.test.ts` with `readJsonc` helper and INF-02 assertions
using it. `tsconfig.base.json` untouched.
</objective>

    Implementation requirements for `readJsonc`:

    1. Signature: `function readJsonc(filePath: string): unknown`
    2. Read the file with `fs.readFileSync(filePath, "utf8")`.
    3. Strip comments using two sequential replacements on the raw string, before calling `JSON.parse`:
       a. Strip `/* ... */` block comments (non-greedy, single-pass, handles multi-line).
       b. Strip `// ...` line comments — but ONLY outside JSON string values.
          A correct and simple approach: use the regex
          `/("(?:[^"\\]|\\.)*")|\/\/[^\n]*/g`
          with a replacer that returns the captured group 1 unchanged when it matched (i.e., the
          token is inside a string) and returns `""` otherwise (i.e., the token is a `//` comment).
          This avoids stripping `://` in URLs inside string values.
    4. Call `JSON.parse(stripped)` and return the result typed as `unknown`.
    5. No `any`, no `@ts-ignore`. The replacer function must be typed explicitly:
       `(match: string, stringLiteral: string | undefined) => string`.
