<threat_model>
## Trust Boundaries

| Boundary | Description |
|----------|-------------|
| git commit → lefthook → gitleaks | Staged files pass through gitleaks before any commit is accepted |
| developer → commit message → commitlint | Commit messages validated before git accepts them |
| git push → lefthook → tsc | TypeScript compilation runs before push is accepted |

## STRIDE Threat Register

| Threat ID | Category | Component | Disposition | Mitigation Plan |
|-----------|----------|-----------|-------------|-----------------|
| T-1-01 | Information Disclosure | EC private key committed via git | mitigate | gitleaks pre-commit (staged scan) + CI full-history scan (Plan 04). Two-layer defense per D-06. |
| T-1-01b | Information Disclosure | SECRET= / API_KEY= in .env committed | mitigate | .gitleaks.toml generic-env-secret rule with __fixtures__/ allowlist. .gitignore blocks .env* from tracking. |
| T-1-02 | Tampering | gitleaks binary integrity (brew install) | accept | gitleaks distributed via Homebrew formula with checksum validation. Known OSS project github.com/gitleaks/gitleaks. Acceptable risk for developer tooling. |
| T-1-03 | Tampering | Bypass via --no-verify on git commit | mitigate | CI full-history gitleaks-action scan (Plan 04) is the second layer that cannot be bypassed from local. |
| T-1-SC | Tampering | npm/pnpm installs | mitigate | All packages in Package Legitimacy Audit — [APPROVED]. lefthook postinstall downloads binary from official github.com/evilmartians/lefthook releases — expected behavior documented in Package Audit. |
</threat_model>
